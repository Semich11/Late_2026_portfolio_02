Finance Cap

A gamified financial literacy platform for children. Learners pick a course, work through lessons and quizzes, and track their points, hearts and progress.

Live siteGitHub
Front end
Next.js 15, React 19, TypeScript, Tailwind CSS
Back end and data
Clerk, Drizzle ORM, PostgreSQL (Neon), Zustand
My role
Design, build and deploy on Vercel
Decisions and tradeoffs
Goal
Make financial literacy approachable for children with short lessons and visible progress.
Choice
A layered structure of schema, cached query functions, server actions and UI components. Each layer has one job, so a database change does not ripple into the pages.
Access
One Clerk middleware guards every route except the landing page, so access rules live in a single place.
Tradeoff
A separate admin dashboard speeds up content management but adds a second interface and a set of REST routes to maintain.
Next time
Add automated tests around the query layer and server actions, with a check that runs before each deploy.

Engineering practice

SOLID principles and design patterns in real code

Where they show up in my projects.

I design with SOLID principles and use patterns where they pay for themselves. These are the places they appear in the work above.

  1. ResponsibilitySingle responsibility: Finance Cap splits schema, cached queries, server actions and UI components, so each module has one reason to change.
  2. Open/closedButton styles are defined as variants with class-variance-authority, so new looks are added without editing the component's internals.
  3. ProviderJSM Headphones shares cart state through a React Context provider instead of passing props through every component.
  4. StoreFinance Cap keeps client UI state, such as the exit modal, in a small Zustand store.
  5. Data layerPages and server actions read through query functions wrapped in React cache, not straight from the database.
  6. MiddlewareOne Clerk middleware protects every route except the landing page, so access rules live in one place.
